# 快速上手

从"装好 Jin"到"完成第一个被批准、实现、并验证过的变更"的短路径。

## 1. 安装并打开项目

从 [GitHub Releases](https://github.com/ZYF93/Jin/releases) 下载对应系统的安装包，打开 Jin，选择**打开项目**（或**新建项目**）。在指向真实仓库前，可以先体验内置 demo。

首次打开一个 Git 仓库时，Jin 会创建项目文件并扫描源码树：

```text
.jin/config.yaml    # 项目名、扫描根、忽略规则、UI 默认值
.jin/wal.jsonl      # 已批准的架构历史（账本）
.jin/.gitignore     # 让本地缓存不进 Git
.jin/cache/         # 本地数据库、LSP 数据、嵌入、临时文件（被忽略）
```

也可以在命令行初始化（幂等——绝不截断已有的 WAL）：

```bash
pnpm run jin:init --name "sample-app" --languages typescript,react
```

## 2. 配置 Provider

在 **设置 → Provider** 里选协议、填端点与模型，需要密钥就填密钥。完整列表、2026 模型预设、自定义请求头、可选的网页搜索端点见 [Provider 与模型](providers.zh-CN.md)。

最小示例：

```text
OpenAI 兼容
  Base URL:  https://api.openai.com/v1
  模型:      gpt-4.1
  API Key:   你的密钥

Ollama（本地）
  Base URL:  http://localhost:11434
  模型:      qwen3:8b
```

有系统安全存储时凭据存在那里。模型刷新找不到你的模型时，在模型框里直接输入精确 ID。

## 3. 看懂架构

打开**架构画布**（或 Intent 面板）。Jin 展示 L0 模块、L1 文件/组件、facet，以及在有语言服务器时补充的 LSP 符号与诊断。这张账本就是之后约束每次实现的"唯一事实源"。

> 提示：如果你在意某语言的符号级上下文和诊断，就装它的 LSP server。没装也能扫描，但该语言的符号事实会缩水。

## 4. 提需求并批准

在聊天里描述你想要的**行为和约束**，而不是无边的"整理一下项目"：

> 给项目列表加服务端分页。翻页时保留当前筛选条件，展示加载与空态，并为翻页控件加测试。不要改动项目 API 的返回格式。

Jin 把它变成一个 **intent** 和一份**架构变更提案**：受影响的模块/符号、影响面、以及自然语言的验收标准。**审的是这份提案，不是 diff。** 如果提案指错了架构位置，在批准前先修正需求。

## 5. 实现并自我验证

批准后：

1. 实现在隔离工作区里暂存，被限制在批准的文件范围内。
2. Jin 跑项目的 **test / typecheck / lint** 脚本；有失败就把失败输出喂回去做**一轮自修**，再重跑。
3. Jin 重扫并检查**批准的架构是否真的落成**（一致性校验）。
4. 编辑前已打了一个 **Git checkpoint**；结果被记为一个 WAL 版本。

## 6. 审阅与提交

审阅实现结果与架构检查。想让队友共享已批准的架构历史时，把 `.jin/wal.jsonl` 和代码一起提交。Git 合并驱动保证并发分支的账本记录互不覆盖。

### 撤销

每轮实现都生成了 checkpoint。如果改错了，在聊天里点**撤销**即可把工作区恢复到实现前状态——不动 `HEAD`，你可以自行查看、提交或丢弃。
